PART 2 — PROJECT OBJECTIVE
==================================================

Build a secure, AIOps-driven observability platform using a two-tier architecture.

CORE DIRECTION:

- Local-first data security.
- Metadata-only SaaS communication.
- AIOps-driven operations.
- Global-ready architecture.
- Future Autonomous Ops.

TIER 1: LOCAL CUSTOMER ENVIRONMENT

The local collector must:

- Collect infrastructure, application, network and security telemetry.
- Filter and normalize telemetry locally.
- Redact sensitive information.
- Remove secrets and credentials.
- Aggregate and summarize telemetry.
- Perform local analysis.
- Apply data transmission policies.
- Keep raw logs and sensitive data local by default.
- Send only approved metadata to the SaaS platform.
- Buffer data during connectivity failures.
- Retry transmission after recovery.
- Maintain auditable egress records.

TIER 2: CENTRALIZED SAAS PLATFORM

The SaaS platform must:

- Receive approved metadata only.
- Support multiple tenants.
- Display infrastructure health.
- Display network health.
- Display security events.
- Display collector fleet health.
- Detect anomalies.
- Correlate related events.
- Generate prioritized incidents.
- Generate explainable recommendations.
- Provide dashboards and alerts.
- Enforce tenant-level separation.
- Support future policy-controlled Autonomous Ops.
